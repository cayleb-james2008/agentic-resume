Principles

What “good” means here.

These are the rules I use when polishing repos and this site for technical hiring. They’re meant to be checkable, not decorative.

  • Label the claim. Verified, unverified, or refuted. Marketing language doesn’t erase uncertainty.
  • Equal presentation, honest scope. No single employer or case study gets a hero slot that crowds out the rest of the work.
  • Stranger try-path. Clone, install, run — or open a live URL — without a private walkthrough.
  • CI is evidence. Documented green checks on the default branch beat aspirational READMEs.
  • Motion serves clarity. Animation is welcome; it never blocks reading. prefers-reduced-motion is respected.
  • Mobile is not an afterthought. Primary paths work on a phone-width viewport without horizontal panic.
