Independent engineering project · October 13, 2026

Sophos

A coding-agent desktop connecting selected profiles and local model catalogs to real daemon sessions, with durable transcripts and restart recovery.

Profile to session

A selected profile supplies its system prompt when creating a real daemon session. Durable transcripts survive restart, and the UI distinguishes the daemon prompt from safety or tool-policy hints that it does not enforce.

Local model setup

Users can discover or register a loopback model endpoint and make its catalog available to the daemon. Core tests verified catalog registration, profile-to-session delivery, transcript persistence and restart recovery.

Working desktop tools

Session context comes from the daemon, and context summarization calls its real compaction operation. Provider keys are stored separately from general settings. Local model configuration preserves existing endpoints, and missing credentials or unsupported operations return clear errors.

Verification

Automated checks cover profile delivery, local model catalogs, durable transcripts, restart recovery and credential handling. Windows CI verifies native containment, staged runtime inputs, lifecycle behavior and installer construction. A clean source-head installation and live model inference remain separate acceptance checks.

Attribution

Sophos integrates an existing coding-agent runtime. The independent work covers the desktop interface, profile delivery, provider configuration, lifecycle behavior and build provenance.

Evidence

Public Sophos repository. Profile, session, local catalog and recovery checks are recorded in the repository. Advanced interface previews are kept separate from the native working controls.
