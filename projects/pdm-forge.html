PDM Forge — governed vault-simulator pipeline

SIMULATOR — no SolidWorks execution, no vault connection claimed anywhere on this site.

PFV-100 originality note: the PFV-100 valve family is an original fictional design; it contains zero Lee Company CAD, drawings, part numbers, or product data.

§What it is

PDM Forge is a governed engineering-change pipeline for a fictional valve family. A SIMULATOR vault handles check-in/out, versions, permissions, and a WIP → Released state machine. A CAD worker rebuilds the PFV-100 family as REAL Linux-native CAD (CadQuery/OCCT) — NOT SolidWorks — emitting STEP files and kernel-measured properties. A deterministic policy gate of 8 rules decides; a human approves; automation runs; a hash-chained ledger records. The commercial-PDM adapter is written to spec and NEVER CONNECTED — to spec only. Parity tests (receipt: r3-b12-parity.log) exercise both adapters against the same contract.

§Porting to a licensed environment

This system is designed to port: domain, policy, ledger, gate, and workflow sit behind narrow adapter seams (IPdmVault / IPermissionProvider / IEngineeringWorkflow), and the commercial adapter is written against the documented SOLIDWORKS PDM Professional API. The rule is: swap the adapter, not the system — the seam is the only thing designed to change. Licenses were not purchased because this is self-funded work; the port is deliberately engineered and explicitly untested.

Files that change

  • The adapter implementation only (the commercial-PDM adapter project: connection, login, vault calls, mapped to the same contract the simulator satisfies).

Files that stay identical

  • Domain workflow table, policy limits (policy-limits.json) and gate evaluation, hash-chained ledger, control-plane orchestration, CAD worker outputs and their receipts.

What the real adapter already implements to spec

  • The full vault contract surface the simulator satisfies — add/get, checkout/checkin guards, illegal-edge refusal, role refusal, honest labelling — asserted by the same 6-case parity contract, 12/12 (receipt: receipts/r3-b12-parity.log). Unconnected calls refuse closed with NEVER CONNECTED — TO SPEC ONLY, never a silent pass.

What must be verified on a licensed Windows host

  • The EPDM.Interop.epdm reference binding against the installed PDM client version.
  • Vault login against a real vault view (credentials, vault name, working-folder mapping).
  • Admin add-in permission behaviour (the add-in loads, permission denials surface as refusals, not silent skips).
  • A full re-run of the parity contract plus the fault suite against the licensed host before any release claim.

This has NOT been executed against a licensed vault. WHAT REMAINS UNTESTED is listed below; the B12 parity result is seam evidence — the contract holds on both sides — not a claim about any company's systems, and compatibility with any company's systems is never claimed here.

§What remains untested

  • No SolidWorks execution — all CAD is Linux-native CadQuery/OCCT.
  • No execution against a production vault — the adapter never connected.
  • No Windows-host verification — no licensed-client run, no vault login, no add-in load test.
