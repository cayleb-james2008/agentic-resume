Independent engineering project · November 6, 2026

DSH Fleet

A ticket-driven harness that gives fleets of AI agents work as tickets — and only accepts work verified on the real thing.

Dynamic swarms, no standing bench

There is no standing bench of named agents. Each ticket or goal spins up a dynamic swarm shaped to that task: it decomposes the goal, spawns its own sub-agents, does research, authors or reuses skills, and dissolves when the work lands.

Guided by research, not one pattern

The harness is guided by a harness-engineering research base rather than any single pattern. Preferences built into the harness govern first; where no preference covers an area, a recent skill is sourced before raw model knowledge is used, and reusable work is packaged back into skills and tools.

Verification and gates

Verification is one tool among several. Work only counts as done when an independent checker verifies the real artefact — the system has caught its own agents filing false “done” reports, each one found by re-checking the primary source, not the agent’s summary. Human approval gates cover anything that matters.

The Omni Loop

The Omni Loop is my own recursive self-improvement architecture and every swarm's iteration engine: attempt, measured result, rewrite the approach, next iteration — up to 3 iterations per approach, then the approach is wiped and replaced. It is also applied to the fleet itself after every ticket, gated: a candidate version ships only on a fresh checker's measured win against the current version on a fixed scorecard (checker-pass rate, cost per checker-passed task, frozen regression set of past tickets). Any regression rejects the candidate outright; shipped improvements are versioned and reversible; the loop may propose gate or scorecard changes but never edits its own gates.

The preference/skill ladder

Inside every swarm: (a) my preferences, built into the harness, govern first; (b) where no preference covers an area, a skill created or updated within the last 30 days must be sourced before acting; (c) raw model knowledge last — and reusable work is packaged back into skills and tools. The design draws on Anthropic/OpenAI multi-agent research, the MAST failure taxonomy, Elephant-Goldfish spec review by fresh-context reviewers, and good-views verification — an independent observation of the artefact itself, never a re-read of the maker's summary — with cost-per-passed-task as the efficiency metric. Guidance, not a cage.

Distributed, recursively self-improving

This is infrastructure, not a ticket fulfiller. The swarms revise the fleet's own workflows, plugin behaviour, Omni Loop and skill library from measured job outcomes, so the system that does the work is itself improved by the work. It spans desktop, Windows VM, phone VM and browser execution surfaces, and Slack is its bring-your-own-agent coordination layer, connecting outside agents into the same operating protocol.

Status

In active development. The fleet runs my whole operation — software builds, research and the OpenBell trading desks.

Evidence

The fleet's code repository is private; this page is its public record. In active development; no completion claim is made for it.
